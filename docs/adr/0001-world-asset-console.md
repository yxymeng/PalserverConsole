# 使用面向任务的只读世界资产台

世界数据不再以玩家、帕鲁、公会和据点的通用实体浏览器为产品模型，而采用面向管理员任务的只读世界资产台。管理员首先确认存档快照可信度，再围绕帕鲁照护、物资位置、资产归属和玩家主要进度完成浏览；这样比按内部数据表组织页面更符合日常管理，但需要同步扩展解析、派生缓存、查询 API 和前端信息架构。

## Considered Options

- 保留通用实体浏览器，只调整样式：改动较小，但无法提供物品聚合、照护判断和任务型筛选。
- 直接复制参考项目的仓库与帕鲁页面：交付较快，但会引入不一致的视觉体系、数据模型和许可链。
- 构建当前项目原生的世界资产台：改动范围最大，但能保持只读安全边界、稳定 ID 关系、ZOE 视觉体系和可验证的数据来源。

## Consequences

- 世界缓存仍是可重建的只读派生模型，真实存档保持不变；
- “仓库”固定表示物品与材料，“帕鲁名册”覆盖玩家、队伍、终端和据点帕鲁；
- 个体标记、资质和照护状态成为不同领域概念；
- 存档快照不得表述为实时状态；
- 元数据必须固定版本、许可可追溯且运行时离线；
- 页面结构采用继承现有视觉体系的“总览门厅”，不把单个页面改成独立 HUD 风格。
